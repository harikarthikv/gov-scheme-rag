# Profile Extraction Workflow

To perform highly accurate vector retrieval, the system must translate natural conversational text into structured demographic data. This is handled by the Profile Extraction workflow (`server/matching/profile_extractor.py`).

## The Challenge
Users do not speak in JSON. They say things like, *"I'm a poor farmer with two kids."* 
A standard vector search using that exact phrase might retrieve schemes about "poor farmers" but miss critical schemes explicitly targeting "annual income < 100000" or "family size > 3".

## The Solution: Conversational Inference

Before hitting the vector database, the entire conversation history is passed to the primary LLM (Gemini) with a highly specific extraction prompt.

### 1. The Prompt
The LLM is instructed to extract explicit facts and infer implicit ones.
- **Explicit**: "I am 30" -> `{"age": 30}`
- **Implicit**: "I just finished 12th" -> `{"age": 18, "education": "12th pass"}`
- **Implicit**: "My husband passed away" -> `{"marital_status": "widowed"}`

### 2. The Output Schema
The LLM is constrained to output exactly two JSON keys:
1. `profile`: A structured dictionary of inferred fields (age, gender, state, occupation, annual_income, caste_category, disability, education, marital_status, family_size).
2. `missing`: A list of the most critical fields still unknown that would meaningfully improve scheme matching.

### 3. Graceful Degradation (Ollama Fallback)
If the Gemini API rate limits (429) or throws an auth error (400, 403), the extraction logic gracefully degrades:
1. It immediately queries `utils.llm.is_ollama_available()`.
2. If the local Ollama daemon is running, it routes the exact same extraction prompt to the local `qwen3:0.6b` model.
3. It strips the `<think>` reasoning tags generated by Qwen3 and parses the JSON.
4. If both Gemini and Ollama fail, it returns an empty profile `{}`, allowing the system to fall back to a raw semantic search using the user's raw message.

## Usage in Retrieval
The extracted structured `profile` is then compiled into a dense, descriptive string by `build_query()` in `eligibility_chain.py`:
> *"I am 30 years old. from Tamil Nadu. working as a farmer. With annual income of Rs 50000. Which government schemes am I eligible for?"*

This dense string generates a much higher quality vector embedding than the raw conversational input, resulting in vastly superior ChromaDB retrieval.
